# AI IT-Helpdesk для сотрудников (прототип)

Telegram-бот первой линии IT-поддержки на Claude API. Сотрудник пишет обычным языком («не работает VPN»,
«как подключить принтер на 3 этаже?», «забыл пароль от почты»), а бот:

1. **Уточняет контекст** — задаёт по одному вопросу с кнопками (ОС, офис, устройство).
2. **Ведёт по интерактивному гайду** — короткие шаги с кнопками «✅ Сделал, что дальше?», «🎉 Заработало», «❌ Не помогло».
3. **Ищет в базе знаний** — локальные `.md`, Notion, Confluence — и объясняет простыми словами.
4. **Создаёт заявку и зовёт человека** — в Jira Service Desk (или в файл-заглушку), с окружением, списком
   выполненных шагов и всей перепиской; дублирует уведомление в чат IT-отдела.
   Кнопка «🆘 Позвать специалиста» и команда `/human` работают в любой момент.

## Какая модель отвечает

`LLM_PROVIDER` в `.env`: `gemini` — бесплатный тариф Google (ключ: https://aistudio.google.com/apikey;
лимиты на число запросов, запросы могут использоваться Google для обучения, доступен не во всех странах),
`claude` — Claude API (платно, качество выше). По умолчанию (`auto`): Gemini, если указан `GEMINI_API_KEY`.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите TELEGRAM_BOT_TOKEN и GEMINI_API_KEY (или ANTHROPIC_API_KEY)
python -m helpdesk.channels.cli           # проверка в консоли, без Telegram
python -m helpdesk.channels.telegram_bot  # запуск бота
pytest                                     # тесты (без сети и ключей)
```

Токен бота — у [@BotFather](https://t.me/BotFather) (`/newbot`). Чтобы бот присылал эскалации в чат админов,
добавьте его в группу IT и укажите её id в `IT_SUPPORT_CHAT_ID`.

## Как это устроено

```
Telegram / CLI (channels/)      ← только отрисовка текста и кнопок
        │
   Engine (engine.py)           ← сессии, кнопки, прохождение гайдов, эскалация
        │
   HelpdeskAgent (agent.py)     ← Claude + инструменты:
        ├─ ask_user               уточняющий вопрос с кнопками   (ждёт ответа человека)
        ├─ start_guide            запустить гайд из data/guides  (ждёт итога гайда)
        ├─ search_knowledge_base  kb/: local · notion · confluence
        └─ create_ticket          tickets/: jira · mock
```

* **Гайды детерминированные.** LLM выбирает гайд и вариант (Windows/macOS), а шаги показываются строго из YAML —
  инструкции предсказуемы, IT-отдел правит их без программиста. Итог гайда (помогло / не помогло / на каком шаге
  остановились) возвращается модели, и она решает: закрыть вопрос или создать заявку.
* **Свободные вопросы** — через поиск по базе знаний; модель проинструктирована не выдумывать внутренние адреса и
  правила, а брать их только из найденных статей.
* **Безопасность:** бот никогда не просит пароли и коды; признаки фишинга/взлома → заявка с высоким приоритетом.

## Настройка под компанию

| Что | Где |
|---|---|
| Гайды | `data/guides/*.yaml` — `id`, `title`, `description`, `needs`, `variants: {windows: [...], macos: [...], any: [...]}` |
| Статьи базы знаний | `data/kb/*.md` — каждый раздел `## ...` ищется отдельно |
| Notion | `KB_SOURCES=local,notion`, `NOTION_TOKEN`; выдайте интеграции доступ к страницам |
| Confluence | `KB_SOURCES=local,confluence`, `CONFLUENCE_*` (email + API token), `CONFLUENCE_SPACE_KEY` |
| Jira Service Desk | `TICKETS_BACKEND=jira`, `JIRA_*`; `serviceDeskId` и `requestTypeId` — из `GET /rest/servicedeskapi/servicedesk` и `.../requesttype` |
| Модель | `CLAUDE_MODEL` (по умолчанию `claude-opus-5-5`), `CLAUDE_EFFORT` (`low` — быстрее и дешевле, `medium` — вдумчивее) |

Содержимое гайдов и базы знаний — **примеры** (адреса `corp.example`, сеть `Corp-WiFi` и т.п.), замените их на свои.

## Модель и API

* Claude API через официальный SDK `anthropic`, ручной цикл tool use, `tool_choice: auto` без параллельных вызовов,
  строгие схемы инструментов (`strict: true`).
* Системный промпт с каталогом гайдов кешируется (`cache_control`) — повторные запросы дешевле.
* Включён серверный fallback (`fallbacks: "default"`): если классификатор безопасности отклонит запрос,
  API сам повторит его на запасной модели. Отключается сменой модели или удалением двух строк в `agent.py::_call`.

## Что дальше (не входит в прототип)

* Хранить сессии в Redis/Postgres вместо памяти процесса (сейчас при перезапуске диалоги сбрасываются).
* Двусторонний чат со специалистом прямо в Telegram (сейчас — тикет + уведомление в чат IT).
* Векторный поиск по базе знаний и периодическая индексация Notion/Confluence.
* Адаптеры Slack и MS Teams: достаточно написать новый `channels/*.py`, движок общий.
* Дашборд: доля решённых без человека, частые темы, время до решения.
